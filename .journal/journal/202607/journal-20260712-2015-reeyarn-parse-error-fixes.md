- Core Architecture > Resolver/pool: Fixed the "file not found" class (`f4b796a`) by decoding percent-encoded paths before opening them — `_resolve_url()` returns `pathlib.Path(...).as_uri()`, which percent-encodes the path, and four sites then stripped the `file://` prefix with a bare `re.sub()` and handed the remainder to lxml as a filesystem path, so any ESEF package with a space, `+` or parens in a name failed to load its entry-point schema and every one of its linkbases. openesef encoded the path and never decoded it; this was our bug, not a malformed filing.
- Core Architecture > Resolver/pool: Established that the same fix covers `%2B`/`%28`/`%29`, not just `%20` — independently corroborated by the proj_esef session, which found 43 URL-encoded schema paths across both the EU and German corpora (home24, Lenzing, Agora, Citibank PL, Rathbones) and ~510 "No such file" + 67 "Failed to attach schema" events.
